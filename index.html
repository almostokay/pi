Four house rules that apply to every single operation

Let it finish

  • Procurement and Enquiry both read the entire stock sheet — that's 3–4 minutes, every time.
  • Don't close the tab, click other menus, or start typing while it says Working….

Work top to bottom

  • The six chapters here are numbered in the order you'd normally use them in a day.
  • Add New Orders first, Process AWB last — each one assumes the previous step is already done.

Exact text matters

  • The tools look for exact words — p, completed — not anything that "means the same thing."
  • Close-but-not-exact entries are silently ignored, not flagged as an error. Cancelled / Cancel Request text is the one exception — that check is deliberately spelling-tolerant.

One person, one operation

  • Avoid two people running PI Tools operations on the same sheet at the same time.
  • If something looks stuck or wrong, stop and ask — don't run it again "to see if that fixes it."
Chapter 01 · Menu item: "Add New Orders"

Getting fresh orders onto the shelf

Every order starts life in a raw CSV export from the website. This step reads it, quietly throws out anything you already have, and sorts the rest into "ready to ship" and "pre-order" piles — without you having to eyeball a single row. It now also catches cancellations automatically, every single time you import.

Reads: your freshly-imported CSV tab Checks against: main + preorder Writes to: NEW + NEW PREORDER Also catches: Cancelled / Cancel Request lines

What's actually happening

The tool looks at the top few rows of your imported sheet to find the header automatically — you never need to trim or align anything by hand.

Then it checks every single order line against what's already sitting in main and preorder. Anything with the same Order Number + Item ID is treated as a duplicate and quietly skipped.

What's left gets sorted: if "Order Status" contains the word pre anywhere in it, the line goes to NEW PREORDER. Everything else goes to NEW.

Important: this only fills NEW and NEW PREORDER — it does not touch main directly. Moving those rows into main/preorder is your last manual step, shown below.

How the data moves

Note: diagram labels stay in English since they match the exact tab names in the sheet.

If your export also has Cancelled / Cancel Request lines

You don't need a second step, and you don't need to sort anything out beforehand. Every time you run Add New Orders, it first quietly checks the whole import for any line whose Order Status says Cancelled or Cancel Request — including misspellings like "canceled" or "cancle."

Those lines are handled completely differently from a normal new order:

1. They are never queued into NEW or NEW PREORDER — there's no point queuing a book to fulfil that's already been cancelled.

2. If that same Order Number + Item ID already exists in main, preorder, NEW, or NEW PREORDER, that row is coloured a medium red, and its status text is struck through with "Cancelled" or "Cancel Request" appended right after it — in both the status and Order Status columns.

3. Every cancelled line — matched or not — is logged into a tab called Cancelled Orders, so you always have one place to look back on everything that's ever been cancelled.

One safety net: if a row is already completed or shipped, it is never auto-cancelled or coloured — a shipped book needs a human to handle the refund/return, not a silent status change. The popup will tell you if this happened so you can review it yourself.

Where a cancelled line goes instead

Step by step

7 steps · ~2 minutes
1
Export the orders CSV from the website admin panel

This is the raw order export you're already familiar with — no changes needed before importing it. You don't need to separate out cancellations first; the tool sorts that out for you.

2
Import it as a brand-new tab in this Google Sheet

Use File → Import → Insert new sheet. Google Sheets will auto-name the new tab (usually after the CSV file, e.g. "orders-export"). You're free to leave that auto-generated name as-is, or rename it to anything else you like.

The one thing to avoid: don't name (or rename) this tab main, preorder, NEW, NEW PREORDER, Cancelled Orders, or any other tab name PI Tools already uses. The tool checks which tab is active before it runs, and it will refuse to run if you're sitting on one of those reserved tabs.
3
Click into that new tab so it's the active sheet on screen

Whichever tab is open when you run the tool is the one it reads.

4
Go to PI Tools → Add New Orders

Confirm the popup that appears. If any Cancelled / Cancel Request lines were spotted in the import, the popup will already warn you how many, before you even click through.

5
Let it scan, dedupe, sort, and mark cancellations

This part takes a few seconds. It's comparing every row against your existing main + preorder tabs, and separately checking each line's status for a cancellation.

6
Read the summary popup

It tells you exactly how many new regular orders, new pre-order items, and skipped duplicates it found — and, if relevant, how many Cancelled / Cancel Request lines were found, how many rows got marked in each tab, and how many new lines were logged to Cancelled Orders.

If duplicates skipped = 0 on a re-run of the same file, that's expected — it means nothing new was found. Same logic applies to cancellations already logged before: they won't be logged twice.
7
Copy the rows from NEW / NEW PREORDER into main / preorder

This is the one manual hand-off in the whole chapter — the tool stages the rows for you, but placing them into the live sheets is still your call. Cancelled lines are never in this pile, so you won't accidentally copy a cancelled order in as new.

Skip this and every other PI Tools operation will act like these orders don't exist yet.

Dos & Don'ts

Do

  • Run this first, before any procurement or enquiry work, so main/preorder are current.
  • Read the popup counts before closing it — they're your receipt, cancellations included.
  • Move NEW / NEW PREORDER into main / preorder right away, same sitting.
  • Open the Cancelled Orders tab afterwards if the popup flagged anything "Already Completed/Shipped" — that needs your manual review.

Don't

  • Don't run this while sitting on main or another reserved tab — it must be the fresh import.
  • Don't import the same CSV twice expecting different results — duplicates are blocked automatically.
  • Don't worry when the import tab disappears afterward — that's automatic clean-up, not an error.
  • Don't manually delete or "fix" a red row you weren't expecting — it means that Order Number + Item ID really was cancelled somewhere in your import.

Chapter 02 · Menu item: "Check Cancel Orders"

Marking cancellations on their own

Chapter 01 already catches cancellations automatically whenever you import a new order batch. This chapter is for the other situation: the website (or a customer) has sent you a cancellation update on its own — separate from your usual new-orders cycle — and you just want existing rows in main / preorder marked, nothing else.

Reads: whichever tab is active Marks: main + preorder + NEW + NEW PREORDER Logs to: Cancelled Orders Order-independent — run any time

What's actually happening

Import whatever the website gave you — a dedicated cancellations report, or even a full orders export — into a fresh tab, just like Chapter 01. This tool reads that active tab and looks specifically at the "Order Status" column for anything that says Cancelled or Cancel Request. The check is spelling-tolerant, so "canceled," "cancle," or "cancellation request" are all caught too.

For every cancelled line it finds, it looks for that same Order Number + Item ID in main, preorder, NEW, and NEW PREORDER — checking all four, since a cancelled order might still be sitting in NEW/NEW PREORDER if it hasn't been copied into main yet.

Wherever it finds a match, it colours that entire row a medium red, then strikes through the old text in both the status and Order Status cells and appends "Cancelled" or "Cancel Request" right after it, in the same cell.

Every cancelled line — whether or not a match was found anywhere — gets logged to the Cancelled Orders tab, using the same columns as main plus a trailing "Cancellation Reason." Lines already logged on a previous run are never logged twice.

Just like Chapter 01, any row that's already completed or shipped is left completely untouched — no colour, no strike-through — because a shipped book needs manual handling (refund/return), not an automatic status change. The popup flags these separately so you know to look at them yourself.

How the data moves

Step by step

6 steps · under a minute
1
Get the cancellations update from the website

This can be a report that only lists cancelled / cancel-request orders, or a full orders export — either works, since the tool only acts on the lines that actually say Cancelled or Cancel Request.

2
Import it as a brand-new tab, exactly like Chapter 01

Use File → Import → Insert new sheet. Any name is fine, as long as it isn't one of the reserved PI Tools tab names.

Must contain an "Order Status" column, or the tool will stop and tell you it can't find one.
3
Click into that new tab so it's the active sheet on screen

Same rule as everywhere else — the active tab is what gets read.

4
Go to PI Tools → Check Cancel Orders

If nothing cancelled is found in this import, you'll just get a short "nothing found" message and nothing else happens. If something is found, you'll see exactly how many lines, and a reminder of what's about to be marked, before you confirm.

5
Confirm, and let it mark + log

This runs in a few seconds — it's only scanning four tabs plus writing to the log, not the whole stock sheet.

6
Read the summary popup

It breaks down exactly how many rows were matched and marked in each of main, preorder, NEW, and NEW PREORDER, how many were already Completed/Shipped and left alone, and how many new lines were logged to Cancelled Orders.

A tab showing "(tab not found)" simply means that tab doesn't exist right now — that's not an error, it's just skipped.

Dos & Don'ts

Do

  • Use this any time you get a cancellation update on its own — you don't need to wait for your next new-orders import.
  • Read the per-tab breakdown in the popup so you know exactly what got touched.
  • Manually review anything flagged "Already Completed/Shipped" — that's a refund/return conversation, not a status flip.
  • Run this and Chapter 01 in either order — the result is identical either way.

Don't

  • Don't run this while sitting on main or another reserved tab — it needs the freshly imported tab active.
  • Don't expect it to touch porders, SelAllProc, or any procurement tab — it only ever marks main / preorder / NEW / NEW PREORDER.
  • Don't manually un-colour a red row — procurement already skips red/cancelled rows on purpose, so leaving it marked is what keeps that book from being re-ordered by mistake.

Chapter 03 · Menu item: "Process Procurement - All"

The whole-sheet sweep — use sparingly

This one procures every uncoloured row in main at once. Powerful, but blunt — most days you want Chapter 04 instead. Think of this as the "spring cleaning" option, not the daily one.

Optional — not for daily use Rule: white AWB cell = include Cancelled / Cancel Request rows are always skipped Takes 3–4 minutes

What's actually happening

This tool scans main top to bottom and looks at the background colour of each row's AWB cell — not the text, the colour.

If the AWB cell has no fill colour (plain white / uncoloured), that row is treated as "not yet handled" and gets pulled in for procurement. Any row you've coloured — for any reason, including a cancellation mark from Chapter 01 or 02 — is skipped. As a safety net, it also checks the "status" text itself and skips anything that reads Cancelled / Cancel Request, even if the colour is missing for some reason.

Everything pulled in is checked against every tab in the PI Stock sheet, quantities are totalled per ISBN, and two tabs are produced: one consolidated list, and one split by publisher/distributor.

Because it reads every row in main, it's slower and much less targeted than Chapter 04 — that's exactly why it's the occasional-use option.

How the data moves

Step by step

4 steps · 3–4 min wait
1
Decide which rows you actually want swept up

Look at the AWB column in main. Rows you want procured this way must be left with no background colour.

2
Colour-fill any rows you want excluded

Any fill colour at all — it doesn't matter which one — tells the tool "already handled, skip me." Rows marked red by Chapter 01 or 02 are already excluded automatically.

3
Go to PI Tools → Process Procurement - All

Then wait. It's reading the full order sheet and the full stock sheet.

This is the slowest tool on the menu. Don't interrupt it.
4
Review proc all and PI Procurement All

Same output shape as Chapter 04 — one flat list, one grouped-by-publisher view — just built from the whole sheet instead of a hand-picked list. The popup also tells you how many Cancelled/Cancel Request lines were skipped.

Dos & Don'ts

Do

  • Use this occasionally — a periodic sanity sweep, not a daily habit.
  • Double-check row colours first if you only want a subset procured.

Don't

  • Don't make this your everyday procurement tool — that's Chapter 04.
  • Don't run it expecting a quick result on a large sheet — budget the full 3–4 minutes.

Chapter 04 · Menu items: "Selected Procurement (Fetch P orders)" + "Process Procurement - Selected"

Your everyday procurement engine

This is the one you'll reach for most. You choose exactly which orders to procure by marking them, and the tool does the rest — checking every publisher's stock, totalling quantities, and flagging anything available from more than one place.

Main daily tool Trigger: AWB = p or P, exactly Takes 3–4 minutes

What's actually happening

This chapter is really two clicks working together. First, Fetch P orders scans main for any row where the AWB column is exactly p or P — nothing else counts — and copies just those rows into a working tab called porders.

Then, Process Procurement - Selected reads porders, cleans up each ISBN, and adds quantities together if the same book was ordered more than once. It then checks that ISBN against every single tab in the PI Stock sheet — each tab there represents one publisher or distributor's own list.

If a book is found in more than one publisher's tab, that row gets highlighted light purple and every source is listed together — useful when one distributor is faster or cheaper than another.

Any row whose status already says Cancelled / Cancel Request is skipped here too, so a cancelled book can never accidentally slip into a procurement list.

The result lands in two places: a consolidated master list, and a second tab with a separate little table for each publisher — ready to copy straight into a message or email to that distributor.

How the data moves

Step by step

8 steps · 3–4 min wait
1
In main, mark every order you want procured

Type exactly p or P in the AWB column for that row. Nothing else is recognised — see the table just below for exact examples.

2
Go to PI Tools → Selected Procurement (Fetch P orders)

This copies just your marked rows into the porders working tab, clearing out whatever was there before.

3
Read the confirmation popup

It tells you exactly how many order lines were found and copied — a quick sanity check before the heavy lifting starts.

4
Go to PI Tools → Process Procurement - Selected

This is the step that checks stock, totals quantities, and builds your procurement lists.

5
Wait 3–4 minutes

It's checking every ISBN against every tab in the PI Stock sheet — this is genuinely the slow part.

Don't close the sheet or click into other menus while this runs.
6
Open SelAllProc for the master list

One row per ISBN, quantities already totalled. Light purple rows are available from more than one publisher/distributor.

7
Open SelProcurement to place your actual orders

Scroll to each publisher's own little table and copy it straight into your message or email to them.

8
Go back to main and change the AWB value for everything you just procured

Replace p with the real AWB once you have it, or any placeholder that isn't p/P in the meantime.

This is the single most common mistake: skip it, and the exact same orders get fetched — and procured — all over again next time.

Do

  • Type exactly p or P — nothing else works.
  • Wait out the full 3–4 minutes without touching the sheet.
  • Treat purple rows specially — compare sources before ordering.
  • Update the AWB column immediately after procuring.

Don't

  • Don't use words like proc, pending, PP thinking they'll work.
  • Don't close or refresh the sheet while it says Working….
  • Don't forget Step 8 — it's the #1 cause of duplicate procurement.
  • Don't reach for Chapter 03 out of habit — this is your daily tool.

Chapter 05 · Menu item: "Check Availability (Enquiry)"

A quick "do we have this?" check

No orders involved — this is purely for checking whether a book exists anywhere in your stock network before you promise it to a customer or place an order.

ISBNs go in column A, from row 4 Takes 3–4 minutes No order sheet involved

What's actually happening

Every ISBN you list gets checked against every tab in PI Stock — the exact same search Chapter 04 uses, just without any order data attached.

For each ISBN it finds, it fills in the title, author, publisher, every location it's available ("Available Where"), stock quantity, and regular price. If it can't find the ISBN anywhere, the Status column simply says ❌ Not found.

Cell E1 keeps you posted — it shows Working… while the search is running, then switches to a timestamp with a "X / Y found" count when it's done.

How the data moves

Step by step

4 steps · 3–4 min wait
1
Open the Enquiry tab

Row 3 is the header — leave it exactly as it is.

2
Paste or type ISBNs into column A, starting at row 4

One ISBN per row. Pasted numbers with a stray .0 at the end (an Excel quirk) are cleaned up automatically.

3
Go to PI Tools → Check Availability (Enquiry)

Watch cell E1 — it will say Working… while the search runs.

Don't start typing new ISBNs while it's still working — let the current search finish first.
4
Read the results across columns B–H

E1 updates with a timestamp and a "found" count once it's done — that's your cue it's safe to read the results.

Dos & Don'ts

Do

  • Paste ISBNs as plain numbers — the tool tidies up stray formatting.
  • Give it the full 3–4 minutes on a long list.

Don't

  • Don't touch the header row (row 3) or shuffle the columns.
  • Don't edit column A again until E1 shows a finished timestamp.

05 / 06 · ENQUIRY
Chapter 06 · Menu item: "Process AWB" + a manual website step

From "packed" to "customer notified"

This is the last mile — and the one with the most real-world consequences, because the end of this chapter is an actual email landing in a customer's inbox. Two stages: the sheet does the sorting, the website does the sending.

Needs 3 columns filled: AWB + Logistic + status Ends with a real email being sent Can't be re-sent the same way twice

What's actually happening — in the sheet

Process AWB scans main looking for rows where three things are all true at once: the AWB cell has a real tracking number (not blank, not just "p"), the Logistic cell names a courier, and the status column — the small lowercase one, not "Order Status" — reads exactly completed.

Every row that matches, and isn't already in Tracking Summary, gets appended there with today's date in "Modification Date" and a starting tracking status of shipped.

That "Modification Date" is your handle for the next stage — it's how you'll find "everything scheduled today" a moment from now.

How the data moves

Stage A — inside the sheet

4 steps
1
On every row that's genuinely packed & ready, fill in three columns

AWB = the real tracking number · Logistic = the courier name · status = exactly completed.

This "status" is the small lowercase column near AWB — not the "Order Status" column further along. Mixing the two up is the most common reason a shipment gets missed.
2
Go to PI Tools → Process AWB

Confirm the popup to proceed.

3
Let it scan main and append to Tracking Summary

Only rows with all three fields correctly filled, and not already tracked, get added.

4
Read the popup — "New tracking entries: N"

That's how many rows just landed in Tracking Summary with today's date.

Stage B — on the website (manual, outside this script)

5 steps
5
In Tracking Summary, find today's batch

Filter or sort by Modification Date — anything dated today is what you're about to mail out.

6
Copy those rows into a fresh sheet and save/download as CSV

This becomes the file you'll hand to the website's import tool.

7
Go to the website's tracking import screen and map the columns as usual

Same mapping process each time — nothing changes here run to run.

If this batch has a mix of shipped and partially-shipped orders, map the "status" field too — otherwise everything defaults to "shipped" even the partial ones.
8
Import, and watch the two progress lines

When the second line reaches 100%, every mail in that batch has gone out.

9
Confirm in the Sent folder of order@padhegaindia.in

Your final proof that the batch actually went out, not just that the import "completed."

Dos & Don'ts

Do

  • Triple-check the status column literally says completed before running.
  • Map the status field on import if the batch has mixed shipped / partial-shipped orders.
  • Check the Sent folder afterward — that's your real confirmation.

Don't

  • Don't import the same batch twice through the website — once mailed, that route won't send again (only a manual resend from the order panel can).
  • Don't expect a row to be picked up if status says processing, confirmed, or anything other than completed.
  • Don't leave the Logistic column blank — AWB alone isn't enough, that row gets silently skipped.
